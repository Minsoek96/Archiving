# 첫 방문 전송량의 82%가 글꼴 한 파일이었다

> 첫 방문이 끊긴다는 보고를 받고 운영 빌드를 빈 캐시로 재 보니, 전송량 **2,451KB 중 2,010KB(82%)가 본문 글꼴 한 파일**이었다. 한글 11,172자가 다 든 Pretendard 가변 글꼴 원본이었다. 공식 패키지의 동적 서브셋으로 바꿔 화면에 나온 글자가 든 조각만 받게 했다. 모바일 조건에서 첫 방문 전송량 **2,451KB → 660KB**, 글꼴 **2,010KB → 244KB(14조각)**, load **약 2.8초 → 약 1.4초**가 됐다.
>
> 상태: 서비스에 반영(2026-10). 끊김의 다른 원인(TTS 모델 68MB를 첫 방문에 받기, JS가 돌기 전까지 빈 본문, 마스코트 이미지가 늦게 뜨기)은 따로 다룬다.

## 문제 상황

배포 뒤 iPhone으로 처음 들어가면 화면이 끊기는 느낌이 든다는 보고가 있었다. 한 페이지(`/interview`)에 면접 퍼널 다섯 화면이 다 들어 있어서, 처음엔 JS 크기를 의심했다.

먼저 운영 빌드를 빈 캐시로 열어 무엇을 받는지 쟀다.

| 항목 | 크기 | 비율 |
| --- | --- | --- |
| 전체 | 2,451KB | 100% |
| **글꼴(Pretendard 가변, 1개)** | **2,010KB** | **82%** |
| JS | 350KB | 14% |
| 나머지(HTML·CSS·이미지) | 약 90KB | 4% |

모바일 조건(Chromium, CPU 4배 느림, 4G 9Mbps·지연 150ms)에서는 아래와 같았다.

- 글꼴이 2.85초에 도착하면서 화면 글자가 한 번에 바뀌었다.
- 글꼴이 JS와 대역폭을 나눠 써서 load도 2.8초까지 밀렸다.

## 원인

처음 프로젝트를 세울 때 Pretendard가 Google Fonts에 없어서, 가변 글꼴 원본(`pretendard-variable.woff2`)을 저장소에 넣고 `next/font/local`로 불렀다. 2MB라는 건 알았지만 preload 없이 `swap`으로 미뤄 두면 첫 화면을 막지 않는다고 보고 넘어갔다.

`swap`은 글꼴이 오기 전에 시스템 글꼴로 글자를 그려 줄 뿐, 2MB를 받지 않게 해 주지는 않는다. 모바일 회선에서는 그 2MB가 JS와 같은 대역폭을 나눠 써서, 화면을 그리는 데 필요한 JS까지 늦게 도착했다. 한글 글꼴이 큰 이유는 완성형 한글 11,172자를 다 담기 때문인데, 면접 퍼널 첫 화면에 나오는 글자는 그중 몇백 자다.

## 시도와 버린 것

| 대안 | 크기(첫 화면) | 판단 |
| --- | --- | --- |
| 그대로 두기 | 2,010KB | 버림. 첫 방문 전송량의 82% |
| 상용 2,350자 서브셋 한 파일 | 원본보다 작음 | 버림. 화면에 없는 글자까지 받음 |
| 시스템 글꼴 | 0KB | 버림. 기기마다 글꼴이 달라져 디자인이 흔들림 |
| 조각 파일만 `public/`에 복사 | 244KB | 버림. 92개 파일과 CSS를 직접 관리하고, 버전을 올릴 때마다 다시 복사해야 함 |
| jsDelivr 같은 CDN | 244KB | 버림. 외부 서버에 의존하고, 사이트가 건 교차 출처 격리(COEP `require-corp`) 때문에 CDN 응답 헤더를 따로 확인해야 함 |
| **`pretendard` 패키지의 동적 서브셋** | **244KB** | **채택** |

동적 서브셋은 글꼴을 글자 범위별 조각 92개로 나누고, CSS의 `unicode-range`로 각 조각이 맡는 글자를 적어 둔 것이다. 브라우저는 화면에 실제로 나온 글자가 든 조각만 받는다.

## 결정과 이유

- **공식 npm 패키지 `pretendard`(1.3.9)의 `pretendardvariable-dynamic-subset.css`를 import한다.** 조각이 빌드에 같이 실려 우리 도메인에서 나가므로 교차 출처 격리와 충돌하지 않는다. 버전은 패키지로 관리된다.
- **글꼴 모양은 바뀌지 않는다.** 원본과 같은 1.3.9 버전이고, 원작자가 나눈 조각을 그대로 쓴다.
- **라이선스를 확인했다.** SIL Open Font License 1.1이고 예약 글꼴 이름은 "Pretendard"다. 글꼴 단독 판매를 빼고 웹 사용과 재배포가 허용된다. 글꼴을 수정하지 않고 원작자의 서브셋을 그대로 써서 예약 이름 조건에도 걸리지 않는다.
- **JS 나누기는 보류했다.** 같은 측정에서 JS(350KB, 가장 큰 조각 148KB gz)와 메인 스레드가 50ms 넘게 막히는 구간(6~7번, 합계 약 0.8~1초)도 나왔다. 그런데 처음 온 사람에게는 튜토리얼이 바로 떠서, 화면별로 나눠도 첫 화면에 필요한 코드가 크게 줄지 않는다. 화면별 나누기와 단계를 경로로 나누기 중 무엇이 맞는지도 정하지 못해, 글꼴만 먼저 고치고 JS는 보류로 정했다.

## 결과

같은 조건에서 두 번 재서 비슷했다.

| 항목 | 고치기 전 | 고친 뒤 |
| --- | --- | --- |
| 첫 방문 전송량(모바일) | 2,451KB | **660KB** |
| 글꼴 | 2,010KB · 1개 | **244KB · 14조각** |
| load(모바일) | 약 2.8초 | **약 1.4초** |
| 레이아웃 흔들림(CLS) | 0.0008 | 0 |
| JS | 350KB | 350KB(그대로) |

- 데스크톱 화면은 글자가 더 많아서 17조각·324KB를 받는다.
- 화면 글꼴이 `"Pretendard Variable"`로 적용되고 한글 글자가 이 글꼴로 그려지는 것을 확인했다.

## 한계

- 측정은 Chromium으로 모바일 조건을 흉내 낸 것이다. 실제 iPhone에서 숫자로 재지는 않았다. 사용자는 글꼴이 바뀌는 깜빡임(FOUC)은 원래 느끼지 못했다고 해서, 체감한 끊김의 주원인이 글꼴이었는지는 확실하지 않다.
- 측정 빌드에는 TTS 모델 주소가 없어서, 운영에서 첫 방문에 받는 TTS 모델 68MB가 빠져 있다. 이 다운로드는 웹 워커에서 나가 페이지 단위 네트워크 제한이 걸리지 않아 같은 방법으로 재지 못했다. 끊김의 유력한 다른 원인으로 따로 본다.
- 다른 화면으로 가면서 새 글자가 나오면 그 조각을 그때 받는다. 조각 하나는 20~40KB다.
- JS(350KB)와 메인 스레드가 막히는 구간(약 0.8초)은 그대로다.
